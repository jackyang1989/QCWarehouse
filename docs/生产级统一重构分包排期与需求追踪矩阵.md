## 一、执行总则与刚性业务边界（对应指令 §§00–02、§56）

1. **核心经营范围与明确边界**
   - **保留且深化的三大核心服务**：`Product Inspection`（单品/批量逐件质检）、`Sample Comparison`（2–3 件或多件同屏横向对比）、`Golden Sample Matching`（确认样核验封存与比对）。
   - **明确排除范围（严禁扩展实现）**：不建多检查员抢单市场、不做代采购/代议价/代付货款、不出具认证实验室/CPSC/CE 合规证书、不接在线电子面单开单或承运商自动下单 API、不在 R2 引入客户离席自动扣款。
   - **品牌与语言硬约束**：全站品牌名统一为 **`QC Warehouse`**（单个空格，使用正式 Open QC 几何字标组件）；客户门户、官网、商业报告与对客邮件全英文专业商务表达；仓库端与管理后台全中文运营界面；报告生成经双语规则字典核验，严禁英文报告残留未审核中文。
2. **强制技术与资金不变量（`AGENTS.md` §3）**
   - **强制私有对象存储（§§34–40）**：生产与预发布强制启用真实 `ObjectStorageProvider`（Cloudflare R2 / AWS S3 / Backblaze B2 / 通用 S3 兼容存储），禁止使用本地磁盘目录或 PostgreSQL `BYTEA`（`private_files`）作为正式长期主存储；写入失败时返回真实错误，禁止静默降级或假成功；隔离测试使用独立 HTTP+SigV4 S3 测试服务；原始证据图（`original`）永不覆盖。
   - **隐藏复杂度与零折扣模块化定价（§§03–10、§43）**：内部复杂度分级 `L1`–`L5` 对客户前端完全隐藏，对外展示为检测方案与 `M01`–`M11` 能力组合；初始版本价格引擎默认数量折扣 `volume_discount = 0`；按 §43.2 草案定价精确命中四组黄金算例（1 件基础 `$17.00`、30 件标准服饰 `$405.00`、2 件对比 `$122.00`、1 件确认样 `$135.00`），`L5` 强制转人工核价；正式生效价格调整前不得未授权修改已上线生产价格。
   - **订单领域解耦与独立寄样（§§12、57–58）**：拆分 `Cart / Checkout / Service Group / Purchase Order / Product Line / Variant / Inbound Parcel / Physical Item / Payment Allocation`；客户下单遵循三步购物车（`Add Products` → `Configure Inspection` → `Review & Pay`），移除结账阶段快递单号必填阻塞，付款后再于 `Send Your Items` 登记运单并支持分批到齐独立开检。
   - **复核前真实 A4 PDF 与精准 QA（§§44–50）**：Inspection 完成后在 QA 之前即按结构化 `Report Document Model` 生成候选真实 A4 PDF，QA 员直接在工作台左右对照核验同一份 PDF 与原图/数据，支持单件/单尺寸/单张照片精准退回原工位修改，批准后原子发布同一份 PDF 对象。
   - **仓储、二次账单与物流规则（§§59–65）**：普通样品自对应报告正式发布（`Asia/Shanghai` 自然日）起享 **15 天** 免费保管，超期幂等计费；Golden Sample 采用 **30/90/180/365 天独立付费保管周期**（取消默认 90 天免费）；历史已下单订单保留原 30/90 天政策快照；出库支持 5 种运费计算模式与人民币成本/锁定汇率 USD 报价双轨、菜鸟人工下单发货台、自提/客户叫快递/集运上门开关默认关闭；二次账单支持高熵受限免密 `/pay/[token]` 安全支付页并防御邮件扫描器 `GET` 预取误消费。
3. **开发与 Git 提交规范**
   - 遵循 **先立项对齐 → 对象存储基座 → 商业定价模型 → 客户下单与寄样 → 仓库现场采集与质检 → 报告 PDF 与 QA → 物流发运 → 仓储计费与账单通知 → 容灾监控与全站验收** 的强制依赖链，禁止跳包强开。
   - **每完成一个 `TASK-*` 功能，必须完成代码类型检查、对应自动化集成验证、台账证据登记并立即提交一次干净的 Git Commit**；不越权覆盖并行开发中的他方未提交草稿。
