## 一、执行总则、商业边界与基础运营先行纪律（对应指令 §§00–02、§56、§§84–85、§94）

1. **核心经营范围与明确排除边界（§§00、56）**
   - **保留并深化三大核心自营服务**：`Product Inspection`（单品/批量逐件质检）、`Sample Comparison`（2–3 件或多件同屏横向对比）、`Golden Sample Matching`（确认样核验封存与基准比对）。
   - **明确不做边界（严禁擅自扩充）**：不做多检查员抢单市场、不做代采购/代议价/代付货款、不出具认证实验室/CPSC/CE 合规证书、不接国内电子面单自动开单或预约取件 API、不在 R2 引入客户离席自动扣款。
   - **品牌与双语硬约束**：全站品牌统一为 **`QC Warehouse`**（单个空格，使用正式 Open QC 几何字标组件）；客户门户、官网、商业报告与对客邮件使用专业英文；仓库工作台与运营后台使用清晰中文；商业报告通过双语规则引擎输出，严禁出现未审核自由中文字符。
2. **基础运营先行与无绕过铁律（§§74.1、84–94）**
   - **先可恢复备份，再高风险迁移（§§74.1、92.2）**：在结构调整、对象存储、员工/权限/仓库重构前，先建立真实 `pg_dump` 与存量盘点核验基座（移除 `triggers.length >= 5` 假健康）。
   - **先后台开户/授权/建仓/调度，再业务切片（§§74.1、85–89）**：安全首次 Owner 一次性引导完成后，员工邀请激活、密码/TOTP MFA、恢复、离职交接、动态 RBAC 与仓库/工位/设备/技能/耗材建档必须全部经由真实后台完成，禁止依赖脚本、SQL、`demo switch` 或测试夹具绕过正式入口。
   - **强约束不变量**：
     - 强制使用真实私有 `ObjectStorageProvider`（R2 / S3 / B2 / 通用 S3），生产禁回退本地盘或 PostgreSQL `BYTEA`（`private_files`），原图 `original` 永不覆盖。
     - `L1–L5` 复杂度对客户完全隐藏；`M01–M11` 零默认折扣且精确命中 `\$17 / \$405 / \$122 / \$135` 草案算例；商业/运费/仓储/模板采用 **草稿→校验→非作者独立审批→发布/定时生效→回滚**，严禁绕过审批直接生效并保护历史快照。
     - 订单域 9 实体解耦 + 3 步购物车 `/cart` + 付款后独立 `Send Your Items` + 分批到齐独立开检 + 复核前生成候选 A4 PDF + QA 单点退回并原子发布同份 PDF + 发布后纠错/零费返工闭环（§91.6）。
     - 报告发布（`Asia/Shanghai` 自然日）起享 **15 天** 免费保管（移库/改址/取消出库/报告修订绝不重置免费期），Golden Sample 采用 **30/90/180/365 天独立付费保管周期**（取消默认免费 90 天），历史 30/90 天旧单承诺不变；六维独立订单结案与结案后拒收退件/投诉重开闭环（§91.4）。
     - **每完成一个 `TASK-*` 功能即核验、更新台账并独立提交 Git**；严禁破坏或覆盖并行工作区未提交草稿。

### 2.3 统一导航、路由、动作与字段权限策略（`route-action-permission-matrix` · §§30, 87）

- **单一权威来源**：服务端 `Action / Resource / Scope` 授权契约同时驱动 HTTP 中间件、前端去重侧栏（按 `routeId` 去重解决 `LIF-013`）与按钮可见性。
- **8 种预置兼容角色**：`receiver`、`inspector`、`reviewer`、`warehouse_admin`、`support`、`finance`、`template_admin`、`super_admin`，并开放后台自定义角色（8 大权限域勾选 + 仓库集合/任务/客户/订单作用域交集）。
- **字段级强制脱敏（后端裁剪）**：内部 CNY 快递成本、人工工时成本与订单毛利仅对授权财务/主管/超管返回；完整客户隐私联系字段向仓库一线收货/质检裁减；采购敏感凭证仅向有 `ocr/order_review` 权限员工可见；所有密文密钥仅返回 `****last4`。
- **硬性职责分离（不可被自定义角色关闭）**：同一自然人严禁自审自己制作的 QA 报告、发起的退款审批、人工收款核销、盘点差异调整、销毁审批、商业价格/模板发布或生产恢复。
