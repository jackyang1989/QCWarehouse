## 一、执行总则、终端边界与全业务闭环硬性决策（§§00–02, §46, §53, §56, §59, §65, §§84–89, §95, §§105–116）

1. **核心经营边界与严禁膨胀红线（§§00, 56, 112.1, 113.1）**
   - **自营三大核心服务**：`Product Inspection`（按委托件数/服务组逐件质检）、`Sample Comparison`（2–3 及经批准更多同品类样品横向对比）、`Golden Sample Matching`（封存确认样基准与大货匹配）。
   - **终端产品硬边界（§113.1）**：
     - **公开网站**：响应式 Web（`en-US` 默认 + `/zh/*` 完整中英双语），电脑与手机浏览器均可查价、咨询、注册及下单；**不建独立移动应用**。
     - **客户中心**：**PC Web 优先**，完整兼容普通手机浏览器（查订单、报告/照片/视频、物流、待办、补资料、付款、确认报价、地址、客服及处置）；**客户 iOS/Android 原生 App、PWA 安装与 Web Push 明确延期不开发**。
     - **仓库 PC 作业中心 + 手机无线摄影与移动作业端（`QC Capture`）**：PC 三栏工作台内嵌**可收起/展开停靠/放大**摄影控制台，Wi-Fi 持续配对同时控制多台 **iPhone 与 Android** 手机（A 高位俯拍 / B 低位细节 / C 移动作业，鼠标 `0/3/5/10/15s` 延时快门与定时/手动录像，高清原件直传对象存储）；移动网页优先真实验证，不满足核心画质/持久化/连续运行门禁的平台采用轻量原生摄影组件；手机端按员工实际有效 RBAC 权限动态提供扫码收货/拆包、上架/移库、盘点、拣货/打包、交接、异常及个人任务/通知收件箱（§§87.5, 114.4）。**明确不开发**：USB 脚踏开关、通用手机远程桌面/镜像远控、新增专业单反相机专有驱动/SDK。
   - **商业与功能禁区**：不做第三方服务商入驻与分账；不做代采购/代付货款/卖家退款仲裁；不出具实验室/CPSC/CE/AQL 认证结论；不做电商商品 API/爬虫同步或 ERP 商品主数据；不接国内承运商自动下单/电子面单/上门预约揽收 API（采用菜鸟商家寄件等人工外部下单+内部热敏标签打印）；不做实时在线聊天或 AI 自动客服；不在未授权前提下离席自动扣卡。
2. **本次 `01–116` 终版新增与修订的六大 P0 核心闭环能力**
   - **① 中国行政区划与地址主数据先行 + 集运地址简化（§§59.1–59.7, 60.3–60.6, 73.3）**：基于民政部公开权威来源初始化版本化全国省/地/县完整区划与可核验乡级数据层（兼容直辖市缺地级、东莞/中山等不设区地级市、自治州/盟/旗、历史改名撤并映射与非标准园区别名），**必须先于仓库地址、运费模板、客户地址簿与官网运费计算器落地**；**取消独立集运 `Member ID / 会员编号` 必填字段与拆分规则**，完整保留客户粘贴的收件人或详细地址末尾原有识别文字，不删改、不移动、不重复拼接。
   - **② 全站四端及仓库手机端完整中英双语（`zh-CN` / `en-US`）与多语言报告交付（§§46.6–46.8, 53.1–53.6, 73.5）**：对外默认英文、内部默认中文，采用可扩展 BCP47 locale 注册与唯一业务 ID 多语言关联（禁止写死双列或两套价格/规则）；公开英文保留原路径、中文独立 `/zh/*` 路径并配齐自引用 `canonical` 与双向 `hreflang`；官网顶部/页脚设语言与联系入口，所有正常公开页右下角设**默认收起的轻量非实时联系组件**（§53.6）；正式报告支持客户选定 **`English` / `简体中文` / `Both`**，同一事实快照按语言变体独立生成候选 PDF、逐语言独立 QA 审批后方可完成交付，不重复起算 15 天免费保管期。
   - **③ 统一 AI 服务、按用途模型路由、全动态表单翻译填充与专业语义保护（§§46.4, 53.7–53.13, 65.11, 73.6）**：内置 **OpenAI 官方 API** 与 **OpenAI Compatible API** 双适配器，后台独立「AI 与翻译服务」（`/admin/integrations/ai`）统一管理供应商实例、模型能力/费率版本、**9 类稳定业务用途码（`SUPPORT_INBOUND/OUTBOUND_TRANSLATE`、`INSPECTION_REQUIREMENT/FINDING_TRANSLATE`、`REPORT_TEXT_LOCALIZE`、`NOTIFICATION_TRANSLATE`、`KNOWLEDGE/CMS_TRANSLATION_DRAFT`、`TRANSLATION_CONSISTENCY_REVIEW`）**、版本化提示词、服装专业双语术语库、原子预算预留与 SSRF/PII 脱敏防注入守卫；所有动态多语言配置表单统一具备**失焦/保存草稿去抖自动填充、单字段差异候选、整表一键翻译与按筛选批量翻译**（绝不覆盖已审核人工译文）；**AI 未配置/超预算/故障时 100% 保留原文与完整人工翻译闭环，绝不阻断接单、支付、收货、质检与结构化报告草稿**。
   - **④ 三端通知中心、WhatsApp 官方适配与三栏专业异步客服中心（§§65.1–65.11, 73.4）**：客户中心、运营后台、仓库 PC 与员工手持端共享真实未读铃铛与个人收件箱（已读绝不关闭业务 `Action Required`）；后台独立「通知中心」支持单人/多选/分组人工定向发送、全员公告、定时冻结受众、模板/提醒规则与投递尝试历史；本期完成 **WhatsApp Business 官方 Cloud API** 自动与人工通知软件适配（客户账号独立验证 E.164 号码与同意撤销、24h 窗口与获批模板校验，未获生产凭证默认关闭不阻塞主链路）；升级独立「客服中心」（客户 `/support` 异步时间线 + 后台 `/admin/support` 左队列/中对话与内部备注互斥/右客户 360 三栏工作台 + 复测/补价/修订正式内部协作命令 + 中英双向翻译高风险人工确认）。
   - **⑤ 设备首次授权管理中心、多机位无线摄影与全局媒体证据溯源（§§113–116）**：运营后台独立「设备与工位」授权中心（支持**首次人工批准［默认］ / 仅预登记设备 / 授权人员自助登记［默认关］**，Owner 或仓管主管可在工作台直接审批）；每张照片/每段视频自动冻结 `capture_id`、设备/会话/租约世代、发起与采集责任员工、真实曝光/录制起止时间与时钟偏差可信度、原始 SHA-256 与派生/报告引用链路；独立「全局媒体与证据中心」（`/admin/media`）及设备详情/员工摄影档案支持全维检索、受控预览/Range 播放、客户交付脱敏、保留/隔离与物理存储成本归集。
   - **⑥ 既有生产认证与轻量化合理性红线（`FINAL-01..09`, `R01–R13`, §§105–112）**：保留线上已配置完成的 **Google 与 Microsoft 双 OIDC 正式登录**及香港 Stripe 能力并执行端到端回归；个人经营主体合法配置禁要求虚假 `br_number`，支付/退款绑定具体商户账户实例；三步目录选品购物车（零商品名/SKU/采购单门槛）+ 历史自动沉淀；分离客户追加指令 `approved` 与已持久化任务的 `applied`；落实物理实体选样计划、报告前合法退回（`R07`）、检后 15 天免费保管、客户隐私与统一关户义务引擎及**六维事实一致性守恒对账中心**（范围/实物/地区地址/资金商户/证据与摄影设备/计时租约）。

## 二、排期依赖顺序合理性论证与全量基线审查台账（§§74, 84, 95, 105, 112, 116.1）

### 2.1 为什么必须采用本十二包依赖顺序（严禁倒置返工）

1. **备份与盘点前哨最先（`PKG-0`）**：任何结构迁移或数据清洗前，先落地真实 `pg_dump` 逻辑备份与存量盘点核验，清除 `triggers.length >= 5` 假健康（`LIF-012`）。
2. **基础运营、中国行政区划主数据与设备授权先行（`PKG-1`）**：
   - Owner 引导、主体/商户账户实例、员工开户/MFA/离职交接、11 域动态 RBAC（含移动岗位权限 `§87.5`）是一切后台与现场鉴权的前提；
   - **严格贯彻 §74.1「地区主数据先行门禁」**：`TASK-181` 先完成全国省/地/县+乡级权威区划库、统一选择/解析校验与后台管理，随后 `TASK-182` 自营仓库建档即可直接引用有效地区 ID 与版本快照，下游官网运费工具（`PKG-5`）、客户地址簿与五模式运费（`PKG-9`）全部同源零返工；
   - `TASK-183` 先建立工位、设备档案与**首次人工批准接入策略（§115.6）**，为 `PKG-2` 无线摄影真机验证提供真实授权底座。
3. **私有对象存储、证据溯源契约与双手机无线摄影技术门禁前移（`PKG-2`）**：
   - 严格遵循 **§74.5 与 §116.1「第 113.3 节双平台真实摄影技术验证前移到第 1–2 阶段」**：在完成对象存储直传与 `§115.7` 摄影时间/责任员工/设备溯源契约后，立即在 `TASK-189` 完成真实 iPhone + Android + PC 无线配对、取景、延时快门、高清静态原图/录像直传与本地持久化门禁验证，绝不等到后期 UI 写完才发现浏览器相机画质或持久化不达标。
4. **全站双语国际化、统一 AI/专业翻译平台与统一通信事件底座前置（`PKG-3`）**：
   - 严格遵循 **§74「实施早期先建立第 53 节 locale 资源、AI 供应商/模型路由/提示词/翻译填充组件，以及第 65 节消息/收件人/工单契约，避免完成单语页面后重复返工」**：先在 `PKG-3` 交付中英双语框架、OpenAI/Compatible 统一翻译服务、服装术语保护、全动态表单自动填充/批量翻译组件（§53.9）及统一通信总线（§65.4），使后续标准目录（`PKG-4`）、双语官网与 CMS（`PKG-5`）、客户指令（`PKG-6`）、质检备注预翻译（`PKG-7`）、多语言报告 QA（`PKG-8`）及三端通知客服（`PKG-10`）一次性按双语与事件驱动标准建成！
5. **目录定价内核 → 第四端官网获客 → 客户三步委托 → 仓库无线摄影与选样 → 双语报告 QA → 地区运费与出库结案 → 仓储账务与通知客服隐私 → 六维对账与恢复终审（`PKG-4`–`PKG-11`）**：严格遵循真实商业交易流向与数据依赖，前包输出即为后包权威输入，无任何循环依赖或平行假数据。
